# CS-255: System Analysis and Design

## DriverPass Project Reflection

### Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?

The client for this project was DriverPass, a company that wanted to help students better prepare for their driving tests. The company needed a web-based system where students could take online classes, complete practice tests, and schedule driving lessons. The system also needed to allow employees to manage appointments, track student progress, and access information based on their responsibilities.

### What did you do particularly well?

I think one thing I did well was understanding the different requirements and organizing them into a system design. I was able to identify what students and employees needed from the system and show how they would interact with it through UML diagrams. I also focused on making the system easy to use while including important features such as scheduling, account management, and security.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my project, I would spend more time improving my UML diagrams. Although they show how the system should work, I think adding more details about error messages and what happens when something goes wrong would make them better. For example, I would show what happens when a student tries to schedule a lesson at a time that is already booked. This would help developers understand how the system should handle different situations.

### How did you interpret the user's needs and implement them into your system design? Why is it so important to consider the user's needs when designing?

I interpreted the user's needs by reviewing the information provided by DriverPass and identifying the main features the system needed. I then used those requirements to create diagrams showing how students, instructors, and employees would use the system. I think considering the user's needs is important because the system should solve their problems and make their tasks easier. If developers do not fully understand what users need, they could create a system that works technically but does not meet the customer's expectations.

### How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?

When designing software, I would start by gathering requirements and making sure I understand the purpose of the system. From there, I would break the requirements into smaller parts and use diagrams to plan how everything should work together. In the future, I would continue using UML diagrams, user feedback, and regular communication with the client throughout development. I would also make sure to consider security, usability, and possible problems early in the design process so they can be addressed before the system is completed.
